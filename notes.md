### Понял
- Сборка: препроцессор → компилятор → ассемблер → линковщик. `gcc -E / -S / -c` показывают этапы.
- `#include <stdio.h>` вставляет текст заголовка с объявлениями `printf`; сама реализация в библиотеке (glibc).
- `main` возвращает код завершения ОС: 0 = успех. Смотреть: `echo $?`. На МК `main` не завершается (`while (1)`).
- Комментарии объясняют «почему», а не «что». `/* */` не вкладываются; выключать код через `#if 0 ... #endif`.
- `float` неточен (0.1 не хранится точно), `==` с float нельзя. Литерал `3.14` — это `double`, для float нужен `3.14f`.
- `const` задаётся только при объявлении, потом менять нельзя.
- Деление с округлением вверх: `(a + b - 1) / b` (для a >= 0).
- В целочисленной арифметике **сначала умножать, потом делить**, иначе дробь теряется раньше времени.
- Размер `int` зависит от платформы: на 16-битном МК максимум 32767 → нужны типы из `<stdint.h>`.
- UART 8N1: 10 бит на байт (старт + 8 данных + стоп), байт/с = бод / 10.
- Проверка на здравый смысл: результат, который физически невозможен (136 байт в 64-байтовом пакете), = ошибка выше.

### Понял

**scanf и буфер ввода**
- `scanf` записывает значение в переменную, поэтому ему нужен её адрес: `&x` = «адрес x»
  (операция взятия адреса; ссылок, как в C++, в C нет).
- Ввод сначала попадает в буфер. `scanf` забирает из буфера только то, что подходит
  под формат, остальное остаётся там для следующего вызова:
  - `3.9` для `%d` → прочитано `3`, `.9` осталось в буфере; следующий `%f` сразу получит 0.9, не спрашивая пользователя.
  - `abc` для `%d` → в переменную ничего не записано, `abc` остался в буфере.
  - `12 3.3` в одной строке → каждый из двух `scanf` берёт по числу, второй не ждёт ввода.
- `scanf` возвращает количество успешно заполненных переменных — по нему и проверяют ввод.
- Если ввод не подошёл, переменная не меняется → инициализировать заранее.
  Чтение неинициализированной переменной = UB; ASan/UBSan это НЕ ловят (нужен valgrind).
- `%f` в `scanf` ждёт `float *`, для `double` нужен `%lf`. В `printf` `%f` подходит для обоих
  (при передаче в printf float повышается до double).
- Пользовательский ввод ломает допущения формул: `(a + b - 1) / b` требует a >= 0,
  а `size * 1000` переполняет 32-битный int при размере больше ~2,1 МБ (знаковое переполнение = UB).

**#define и const**
- `#define` — текстовая подстановка препроцессором до компиляции (видно через `gcc -E`).
  Нет типа, нет области видимости (действует до конца файла), в gdb имени нет.
- Макрос-выражение всегда в скобках: `#define THREE (2 + 1)`, иначе `THREE * 10` даст 12.
  В `#define` не ставятся `=` и `;`.
- `const` — настоящая переменная: есть тип, область видимости, видна в gdb.
- «#define экономит память» — для современных компиляторов почти миф: значение всё равно
  лежит в коде, а при `-O2` const подставляется так же. Разница есть только без оптимизации.
- Где `const` реально экономит память в embedded: глобальный `const`-массив остаётся во flash
  (.rodata) и не копируется в RAM при старте.
- В C `const int` — НЕ константное выражение: нельзя использовать для размера глобального
  массива, в `case`, в `#if`. Там нужен `#define` (или `enum`, гл. 16).
- Критерий выбора: нужно ли значение компилятору во время компиляции?
  Да → `#define` / `enum`. Нет → `const`.

**Сборка**
- Часть предупреждений (например `-Wmaybe-uninitialized`) работает только с оптимизацией.
  `-Og` — оптимизация, не мешающая отладке. Добавил в команду сборки.
- `-W` = `-Wextra`, `-pedantic` = `-Wpedantic` (старые имена тех же флагов).
- `-ansi` = `-std=c90`, поэтому `-ansi -std=c99` в примере книги противоречат друг другу

- Стандарт: оставил `-std=c17` — ближе к рабочей практике (STM32CubeIDE по умолчанию gnu11);
  код King (C99) компилируется без изменений.

### Понял

**main и стандарты**
- C89: `main` без `return` → код завершения не определён (получил 39 = возврат `printf`, остался в `eax`). Совпадение, не правило.
- C99+: дойти до `}` в `main` = `return 0`. Только для `main`, для других функций это ошибка.
- `echo $?` показывает код ПОСЛЕДНЕЙ команды: после `gcc` это код компилятора, а не программы.

**Типы в выражениях**
- Тип каждой операции определяют только два её операнда. `*` и `/` выполняются слева направо.
- `4 / 3 * pi` → `4 / 3` = 1 (int / int), дробь потеряна до того, как появился `pi`.
- Если хотя бы один операнд float — операция во float: `4 / 3.0f` работает.
- Важен порядок операций, а не количество float-чисел: `pi * r * 4 / 3` даёт верный ответ.
- `const int pi = 3.14` → pi = 3. Тип переменной урезает значение при записи.

**Как хранится float**
- Двоичная система: точно хранятся только дроби со знаменателем-степенью двойки (0.5, 0.25, 19.5).
  0.1 в двоичной — бесконечная дробь, как 1/3 в десятичной.
- IEEE 754: знак 1 бит, порядок 8, мантисса 23 → около **7 значащих цифр ВСЕГО**, не после запятой.
- `%f` печатает 6 знаков после запятой — это формат вывода, а не точность.
  Напечатанная цифра ≠ правильная цифра (`123456789.0f` печатается как `123456792.000000`).
- Расстояние между соседними float растёт с величиной числа.
- Embedded: Cortex-M0/M3 без FPU (float программно), у M4F FPU только для float → `3.14` вместо `3.14f` = программный double.

**Округление**
- float → int всегда отбрасывает дробь. `x + 0.5f` перед преобразованием = округление до ближайшего (для x >= 0).
- Целочисленное деление с округлением до ближайшего: `(a + b / 2) / b`, напр. `(a + 50) / 100`.
  Вверх — `(a + b - 1) / b`. Обе формулы только для a >= 0.
- Деньги хранить в целых центах: целые числа точны. Общий приём embedded — фиксированная точка
  (милливольты, десятые градуса, Q15/Q31 в DSP).
- Проценты в целых: `x * 5 / 100` — сначала умножать, потом делить.
- Если данные потеряны при вводе (`scanf("%f")` для 1000000.01), дальнейшие вычисления их не вернут.

- Эксперимент менял две вещи сразу (способ деления И тип результата) → нельзя понять, что на что влияет.

**Неинициализированные переменные (упр. 4)**
- `-O0`: мусор со стека от предыдущих вызовов, причём часть значений случайно выглядит как 0.
- `-Og` / `-O2`: везде 0 — компилятор вправе вообще не выделять память, раз это UB.
  Ошибка становится НЕВИДИМОЙ с оптимизацией — опаснее, чем мусор.
- `-Wuninitialized` срабатывает на всех уровнях: переменная не записана ни разу,
  анализ потока данных для этого не нужен (в отличие от `-Wmaybe-uninitialized`).
- ASan/UBSan это не ловят — нужен valgrind или MemorySanitizer в clang.

**Идентификаторы и токены (упр. 5–10)**
- Имена, начинающиеся с `_` или содержащие `__`, зарезервированы за реализацией
  (отсюда `__HAL_RCC_...` в заголовках STM32). Свои имена так не называть.
- `main` и `printf` — обычные идентификаторы, не ключевые слова: `int printf;` компилируется

- `answer=(3*q-p*p)/3;` — 14 токенов. Пробелы обязательны только между токенами,

### Понял

**Тип и форма записи — разные вещи**
- Тип (`int`, `float`, `double`) — как число хранится в памяти.
- Форма записи — как `printf` превращает число в текст: десятичная (`83.1620`)
  или экспоненциальная (`3.02530e+01`).
- `%e`, `%f`, `%g` всегда получают `double` (float повышается при передаче)
  и отличаются только формой записи.

**Спецификатор `%-m.pX`**
- `m` — минимальная ширина поля. По умолчанию выравнивание вправо, флаг `-` — влево.
  Недостающие позиции заполняются пробелами. Поле НЕ обрезает число, если оно длиннее.
- `p` — точность, смысл зависит от буквы:
  - `%d` — минимум цифр (дополняется нулями слева);
  - `%f`, `%e` — цифр после точки (по умолчанию 6);
  - `%g` — значащих цифр.
- Проверять ширину поля — только с обрамлением: `printf("[%-6.2g]\n", x)`,
  иначе пробелы в конце строки невидимы.

**Буквы преобразования**
- `%d` — decimal, десятичное целое.
- `%f` — десятичная запись, по умолчанию 6 знаков после точки.
- `%e` — экспоненциальная: одна ненулевая цифра перед точкой, показатель
  минимум из двух цифр (`e+01`, `e-06`).
- `%g` — выбирает форму `%e` или `%f` по порядку числа (`%e`, если порядок < −4
  или >= точности),    нули в конце дробной части отбрасываются, а если дробная часть пропала целиком — то и точка. Меняет только форму записи, но НЕ значение: `0.0000009979` с `%.2g` → `1e-06`. `%g` с `86.0` даст `86` — это не int, а десятичная форма без нулей.

**Разбор scanf("%d/%d") из addfrac.c**
- Обычный символ в формате (`/`) требует точного совпадения, иначе scanf завершается,
  а несовпавший символ остаётся в буфере.
- Пробельные символы допустимы ПЕРЕД `%d` (он сам их пропускает), но не перед `/`.
  Пробел в формате = «ноль или больше пробельных символов»: `"%d /%d"`.
- Остаток в буфере сразу забирает следующий scanf, не дожидаясь ввода:
  `5/6/7` → второй вызов видит `/7`, возвращает 0, ввод второй дроби пропускается.

**Спецификатор `%-m.pX`**
- По умолчанию выравнивание вправо, `-` включает выравнивание ВЛЕВО.
- Ширина `m` — минимум, а не максимум: `printf` никогда не обрезает число,
  если оно не помещается, поле расширяется (`[%10.6e]` для 3.14159 → 12 символов).
- Знак минус занимает позицию в поле: `[%6.0f]` для -3.14159 → `[    -3]`.
- Точность относится к ВЫВОДУ, а не к переменной: `x` хранит то, что ввели,
  `printf` только решает, сколько знаков показать (лишние округляет, недостающие дописывает нулями).
- Точность не указана → 6 знаков (`%6f` для 3.14159 → `3.141590`). `%.0f` — ни знаков, ни точки.
- `%e` печатает нормализованный вид `d.ddde±xx`: ровно одна НЕНУЛЕВАЯ цифра перед точкой,
  показатель подбирается под неё. Показатель минимум из двух цифр: `e+01`
  (`e+001` печатал старый MSVC, такие примеры встречаются в источниках).
- Тип и формат — разные вещи: `float` — как значение хранится, `%f` / `%e` / `%g` — как печатается.
  Fixed decimal notation = `%f`, а не `%d`.
- `%d` с аргументом `float` = UB: float передаётся как double, а `%d` ищет int
  (на x86-64 даже в другом регистре) → мусор. Ловит `-Wformat` (входит в `-Wall`).

**Округление в printf**
- `(int)x` отбрасывает дробь, `printf("%.0f", x)` округляет. Два разных механизма.
- Ровно половина округляется К ЧЁТНОМУ: 0.5 → 0, 1.5 → 2, 2.5 → 2, 3.5 → 4.
  Round half to even («банковское»), режим по умолчанию в IEEE 754, glibc следует ему.
- Зачем: нет систематического перекоса. 0.5 + 1.5 + 2.5 + 3.5 = 8;
  «половина вверх» даёт 10, «к чётному» — 8. На тысячах операций (усреднение АЦП, суммы) это важно.
- Мои `x + 0.5f` и `(a + 50) / 100` из гл. 2 — это «половина вверх». На половинах они
  расходятся с `printf`, и это ожидаемо.
- Касается только ТОЧНЫХ половин (0.5, 1.5 хранятся точно, знаменатель 2).
  `2.205` из гл. 2 в памяти не половина — там решает ошибка хранения.
- Стандарт C это жёстко не требует. На МК (newlib-nano) `printf` для float упрощён — проверять.

**Возвращаемое значение scanf**
- У `scanf` два «выхода»: число пишется в `x` через `&x`, а возвращается КОЛИЧЕСТВО
  заполненных переменных (int). Поэтому `int items_read = scanf("%f", &x);` —
  x остаётся float, счётчик идёт в отдельную переменную.
- Печатаем его не ради тишины gcc (`-Wunused-result`), а чтобы различать случаи:
  ввод `0` и ввод `abc` дают одинаковый `x = 0.0`, но счётчик 1 и 0.
- Мусор не попадает ни в `scanf`, ни в `x`: он остаётся в буфере, `x` не меняется.
  Поэтому инициализация обязательна, иначе при плохом вводе печатается неинициализированная переменная (UB).

### Понял

**Сопоставление формата scanf**
- В строке формата три вида элементов:
  - `%d` (и `%f`, `%e`, `%g`) сам пропускает пробельные символы, потом читает значение;
  - пробел в формате пропускает ЛЮБОЕ количество пробельных символов, включая ноль.
    Это не «здесь должен быть пробел», а «здесь можно пропустить пробелы»;
  - обычный символ (`/`, `+`) должен совпасть ТОЧНО, иначе scanf останавливается.
- Поэтому в `"%d /%d"` пробел нужен только ПЕРЕД `/`: после `/` его пропустит следующий `%d`.
- Исключение: `%c` пробелы не пропускает, читает любой следующий символ, включая `\n`.
- scanf останавливается в двух случаях: несоответствие ИЛИ конец формата.
  `5/6/7` для `"%d/%d"` — формат кончился, `/7` остался в буфере.
- Все вызовы scanf читают один буфер. Если в нём остались только пробельные символы,
  следующий `%d` их пропустит и будет ждать ввода. Если осталось что-то ещё —
  следующий scanf сразу начнёт с этого остатка, не дожидаясь пользователя.
  (После выхода программы то, что я набрал «для неё», досталось bash.)
- `%d` принимает знак, в том числе `+`. Формат `"%d/%d%d/%d"` без `+` читает
  `5/6+3/4` так же, как с `+`, и пропускает `5/6-3/4` (минус становится знаком числа).
  Что считать ошибкой ввода, решает формат.
- Возвращаемое значение считает заполненные ПЕРЕМЕННЫЕ, а не символы.

**Сторожевое значение (sentinel)**
- Переменная, в которую scanf не записал, сохраняет старое значение.
  Если начальное значение 0, то «не записано» и «прочитан 0» неразличимы.
- Заведомо невозможное начальное значение (`-999`) делает неудачное чтение видимым
  прямо в выводе переменных, а не только по счётчику.
